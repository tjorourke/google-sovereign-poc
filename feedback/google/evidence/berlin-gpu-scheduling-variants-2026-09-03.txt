## 3. Four scheduling variants

Variant 3 (nvidia.com/gpu with no selector) and variant 4 (machine-family: a3)
are rejected at admission by GKE Warden, verbatim:

  [denied by autogke-gpu-limitation]:
    When requesting 'nvidia.com/gpu' resources, you must specify either node selector
    'cloud.google.com/gke-accelerator' with accelerator type or node selector
    'cloud.google.com/compute-class' with existing custom compute class which has at
    least one GPU priority rule.

  [denied by autopilot-machine-family-selection-limitation]:
    Pods with node selector or affinity for "cloud.google.com/machine-family" must also
    specify compute class "Performance".

Variants 1 and 2 use exactly the form Warden asks for:
    cloud.google.com/compute-class: Accelerator
    cloud.google.com/gke-accelerator: nvidia-h100-80gb
  variant 1: nvidia.com/gpu: 8   (a full a3-edgegpu-8g-nolssd node)
  variant 2: nvidia.com/gpu: 1

Both are ADMITTED and then never scheduled:

## 4. Conclusion
  The failure is NotTriggerScaleUp with "didn't match Pod's node affinity/selector",
  not a quota error and not an out-of-capacity error. The cluster autoscaler has no
  GPU node shape it is willing to consider, so it does not attempt provisioning and
  nothing in the output points at the cause. A pod requesting an H100 in the exact
  form GKE Warden demands stays Pending indefinitely.
